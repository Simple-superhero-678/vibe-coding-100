# Day 14 最小修复 · 方案（待拍板）

**问题**（由同伴反馈 + 我的核实共同导出）：移动网络下卡片配图要等几秒，等待期间图框全空，
而**空框与「这条没有图」长得一模一样** —— 第一次来的人分不清「等一下」和「永远没有」。
更硬的一条：线上图源一旦 `error`，`建图()` 直接 `replaceWith(空框)`，**不重试、不恢复**。

**现状（`js/views/portrait.js` + `css/views.css`）**

```js
图.src = 图源 + 条.图 + '.webp';          // 无加载态标记
图.addEventListener('error', () => { ... 图.replaceWith(建空框()); });
```
```css
.portrait,.portrait-empty{ ...同款 1px 淡墨框 + 宣纸底 + 3:4... }
.portrait-empty{border:1px solid var(--hairline)}   /* 与 .portrait 完全一致 */
```

## 选项

| # | 方案 | 改哪里 | 代价 / 风险 | 建议 |
|---|---|---|---|---|
| **1** | **加载态显式化**：加载中的图框显示淡墨骨架微光（复用切部骨架 `.sk-line` 的观感），出图即消失；无图仍是安静空框 → **三态可分** | `portrait.js` 加 `load` 标记 + `views.css` 加一条 `:not(.is-loaded)` 规则 | 小。唯一坑：`prefers-reduced-motion` 下只写 `animation:none` 会把 `opacity:0` 留在原地（09-27 踩过）→ 必须同时补 `opacity:1` | ✅ **推荐**，对症同伴遇到的"等待"，且不引入新视觉语言 |
| 2 | **首屏减重**：非首屏图加 `loading="lazy"`，并把 12 张压到 ≤80KB | 要重新出图 + 改 `portrait.js`（列表用缩略图、详情用原图） | **大**。首条「九尾狐」本来就在首屏，`lazy` 救不了它；重新压图要跑 `postprocess-art.py` + 改资产 + 详情面板也得分尺寸 | ❌ 今天不做（清单明写「不按反馈大改版」） |
| 3 | **失败重试**：`error` 后延时重试一次再给空框 | `portrait.js` 约 6 行 | 极小，但**基本无效** —— 同伴遇到的是"慢"不是"错"，慢的时候不会触发 `error` | ❌ 治不了这次的病 |

## 选 1 的话怎么改（改动面）

- `yizhi/js/views/portrait.js`：`建图()` 里加 `load` 监听打标记（并处理「缓存命中时已经 complete」的情况）。
- `yizhi/css/views.css`：加 `.portrait:not(.is-loaded)` 的骨架样式 + `prefers-reduced-motion` 兜底。
- **不动** `.portrait-empty`（无图仍安静空框）、不动数据、不动 grid/card。
- 验证：本地起服务 → 冷启动截图能看到"加载中"骨架 → 加载完成后骨架消失、图正常；键盘/减少动态效果各跑一遍。

**上限**：今天只改这一处 + 一个兜底媒体查询，不做别的。
