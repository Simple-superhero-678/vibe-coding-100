# 路由与四种状态

> Day 13 的交付口径（站点内文档，`*.md` 不进发布）。
> 改任何一处状态文案前先看这张表 —— 四种状态之所以要分清楚，是因为**出路不同**：
> 把「空」说成「错」，人会去查一个根本没坏的东西；把「错」说成「空」，人会以为数据真的没了。

---

## 一、路由：地址栏是唯一真源

从 Day 13 起，「当前该显示什么」只有一个答案来源 —— 地址栏。
点 tab、按后退、把链接粘进新标签页，走的是同一条路：

```
动作 → 改 hash → hashchange → 按路由渲染
```

| 路由 | 干什么 | 例子 |
|---|---|---|
| `#/部/<部名>` | 部内浏览（五部同式，异兽部叠吉凶筛选、境界部叠序列开关） | `#/部/异兽`、`#/部/神仙` |
| `#/搜/<关键词>` | 全站检索结果（跨五部） | `#/搜/蛇` |
| `#/藏` | 收藏夹 | `#/藏` |
| `#/条/<id>` | 单条详情，**可以发给别人** | `#/条/yishou-001` |

- 空 hash、认不出来的 hash（手打错）→ 一律归一化成 `#/部/异兽`，不白屏。
- 关键词里允许有斜杠（把剩下的段拼回去，不当路径分隔符）。
- 空关键词（`#/搜/`）→ 回部内浏览，不显示一张空结果表。
- `#/条/<id>` 的 id 站里没有（打错 / 条目已下架）→ 悄悄退回部浏览：那不是一个可以「重试」的错。
- `?图源=public`、`?态=空` 这类参数挂在 `?` 上，不参与路由，互不干扰。

**为什么用 hash 不用 history 真路径**：站点在 GitHub Pages，纯静态没有服务端 rewrite，
真路径刷新会被当成找一个不存在的目录，直接 404；要救得额外塞 404.html 并改流水线。
hash 变化不发请求，刷新永远落在 `index.html`，而且天然进历史栈 —— 「返回上一页」白送。

路由层在 `js/router.js`，它**不认识五部、不认识视图**，只认「第一段是哪个词」。
装配层在 `js/main.js`（`按路由渲染` 是唯一入口）。

## 二、四种状态

这里的**数据对象 = 条目列表**（不是单条）。三处地方各自把它取回来、画出来：

| 消费方 | 数据从哪来 | 加载中 | 成功 | 空 | 错误 |
|---|---|---|---|---|---|
| 部浏览 `#/部/x` | 读 `data/x.json` | 淡墨骨架 | 卡片 / 树 / 轴 / 时间轴 / 分组 | 部空态 | 失败块 + 重试 |
| 全站检索 `#/搜/词` | 建全站索引（五部一起） | 「数据还在读」 | 结果列表 | 零结果 + 相近条目 | 「五部数据都没读到」 |
| 收藏 `#/藏` | localStorage 存 id → **跨部回捞** | 面板骨架 | 收藏列表 | 「收藏夹还空着」 | 「收藏夹没读到数据」 |

三者共用同一套视觉语言：**朱砂左竖线 + 一句人话 + 一个能点的出口**（`.zero` / `.load-fail`）。

### 加载中

| 位置 | 反馈文案 | 形制 |
|---|---|---|
| 部浏览 | 「正在读取异兽部…」 | 淡墨骨架：网格部 4 张骨卡（图 + 四行），其余四部 6 条错落短线 |
| 检索 | 「数据还在读，稍等一下再搜。」 | 无骨架（这次要建的是全站索引，形状预告不了） |
| 收藏 | 「正在读取收藏…」 | 4 条错落短线（面板窄，铺满会出滚动条） |

三条共同的规矩：

1. **不转圈** —— 转圈是别人的 UI 语言，与纸墨的调子不合；用「淡墨纸样」预告内容要来。
2. **防闪不用 JS 定时器** —— 淡入延迟交给 CSS（`.skeleton` 的 `animation-delay .12s`）。
   本地读 JSON 只要十几毫秒，骨架还没现身就被真内容换掉了，这里省掉的正是一个「早晚会忘清」的定时器。
3. 屏读只说一句（`role=status` + `aria-busy`），不逐块念「占位、占位」。
   ⚠️ 开「减少动态效果」时，只写 `animation:none` 会把 `opacity:0` 留在原地 → 骨架彻底隐形，
   所以必须补回 `opacity:1`。

### 成功

| 位置 | 反馈 |
|---|---|
| 部浏览 | 站况「异兽部 · 12 条」（境界部带序列词、异兽部带筛选词） |
| 检索 | 站况「全站 · 搜「蛇」 · 3 条」 |
| 收藏 | 面板头「2 条」 |

### 空（三种来源，三套话，别混）

| 来源 | 反馈文案 | 出口 |
|---|---|---|
| **筛选滤空**（有数据、被筛没了） | 「筛「吉祥」下暂时没有条目。」+「这里一共 12 条，换个筛法看看。」 | 「清除筛选，看全部 12 条」 |
| **部本身空**（读到了、就是没内容） | 「异兽部还是空的。」+「数据文件读到了，但里头一条内容都没有 —— 内容还没补上。」 | 异兽部：重试；其余部：去异兽部看看 |
| **检索零结果** | 「没找到「蛇」。」+ 相近条目（写作「X（部名）」） | 点相近条目去搜它 / 「清空，回到异兽部」 |
| **收藏夹空** | 「收藏夹还空着。」+「打开任意一条的详情，点「收藏」，它就会出现在这里。」 | 「去看异兽部」 |

两条硬规矩：**每句空态都必须带一个点得动的出口**；**禁「暂无数据」这类占位文字**（PRD 8.6）。

### 错误

| 位置 | 反馈文案 | 出口 |
|---|---|---|
| 部浏览 | 「异兽部数据没读到。」+「原因：…」 | 重试 |
| 检索 | 「五部数据都没读到，检索暂时不能用。」 | 重试 |
| 收藏 · 全线读不到 | 「收藏夹没读到数据。」+「原因：「异兽、妖怪」部的数据没读到。收藏夹里存的只是条目 id，条目要现去各部取。」 | 重试 |
| 收藏 · 部分读不到 | 列表照常显示，面板顶部补一句「「x」部的数据没读到，那几条暂时显示为「已下架」。」 | —— |

**收藏的「错」为什么单独说**：收藏存的是 id，条目要现去各部取。
以前取不到只会往控制台 `warn` 一句，然后当成「已下架」占位 —— 把「暂时读不到」
说成「已经没有了」。这两件事的出路完全不同（一个该重试，一个该移除），所以现在分开。

## 三、本机怎么把四种状态造出来

本地读一份 JSON 只要十几毫秒，「加载中」肉眼看不见；「错误」原本得把
`data/*.json` 改名才造得出（拍完还得记得改回来，忘了就是线上白屏）。
所以数据层留了一个开关（`js/data.js` 的 `调试态()`）：

| 地址 | 会看到 |
|---|---|
| `http://127.0.0.1:8000/?态=慢#/部/异兽` | 加载中：骨架停 2 秒 |
| `http://127.0.0.1:8000/?态=错#/部/异兽` | 错误：部浏览失败块 + 「模拟读取失败」 |
| `http://127.0.0.1:8000/?态=空#/部/异兽` | 空：部空态（出口＝重试） |
| `http://127.0.0.1:8000/?态=慢#/藏` | 加载中：收藏面板骨架（**先收藏两条**才看得出差别） |
| `http://127.0.0.1:8000/?态=错#/藏` | 错误：收藏面板「没读到」（同上，先收藏两条） |
| `http://127.0.0.1:8000/?态=空#/搜/蛇` | 空：检索零结果 |
| `http://127.0.0.1:8000/?态=错#/搜/蛇` | 错误：全站检索失败块 |
| 不加 `?态=` | 正常：12 张异兽卡 |

- **只在 127.0.0.1 / localhost / file:// 生效**，线上（GitHub Pages）完全忽略这个参数 ——
  调试开关不该让访问者能把站点按成坏掉的样子。
- 放在**数据层**而不是界面层：慢 / 坏 / 没内容说的是数据源的行为。
  将来真接后端，这三种由后端造（延时、500、空结果），这一层原样留着。

## 四、改这块时的三个坑（都是实测踩到的）

1. **`dialog` 的 `close` 事件在元素被 `remove()` 之后就不派发了。**
   「关掉详情要把地址收回来」全靠这个事件，所以关的时候只能 `close()`，
   清理（`remove()`）一律放进 `close` 回调里。
2. **异步渲染会错位。** 接上路由后触发者变多（点链接 / 按后退 / 粘地址 / 敲搜索框），
   从异兽部快速点到妖怪部时，先发出的那次可能后回来 —— 页面显示神仙、地址栏写着妖怪，而且不报错。
   对策是「渲染代」：每按一次路由就 +1，异步回来后对不上号的那次直接作废。
3. **面板内容只能有一个真源。** `播藏()`（进 `#/藏`）和 `同步收藏()`（收藏状态变了）
   都会重画面板，谁后回来谁说话 —— 曾出现「一条说没读到、一条列出 2 条已下架」。
   现在两条路都收进 `铺收藏()`，同一套判定，后画的也不会画错。
