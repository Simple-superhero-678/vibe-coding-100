## 三、3–5 分钟演示提纲

> 节奏：开场 20s → 用户问题 40s → 核心流程 90s → 提示词改写 40s → 验证方式 30s → 平台限制 30s → 后续优化 30s

### 1）用户问题（40s）
「想写仙侠/玄幻小说，但中国神话、妖怪、修仙体系散在十几本古书里，临时查资料慢、还容易写错设定。」
→ 异兽志把**五部 97 条**（神仙/神话/异兽/妖怪/境界）整理成「一查就有、每条都告诉你写小说时怎么用」的查阅站。

### 2）核心流程（90s，边点边讲）
- 进首页 → 点五部 tab（神仙/神话/异兽/妖怪/境界），每部是不同视图形态（谱系树 / 时间轴 / 吉凶网格 / 分组 / 双序列轴）。
- 搜「九尾狐」→ 全站检索，跨部命中；零结果给「相近条目」出口。
- 点一条 → 详情弹层（带 3 秒纸墨转场），每条末尾「写小说时怎么用」。
- 点收藏 → 朱砂闪一下＋「撤销」出口（本地收藏）。
- 拖到底 → **后端检查台**：实时读 CloudBase 的 health / 收藏榜 / 热门榜（真库真行）。

### 3）提示词改写（40s）
「提示词改写」在这站不是功能按钮，而是**每条内容的落点**：把冷门素材翻成可落地的写作提示。
例：条目「九尾狐」→ 不只是释义，而是「可改写成：狐妖伪装入世、以 seduction 推动剧情；或反套路写‘被收编的祥瑞’」。
→ 示范：把用户口头需求「想要一个报恩妖怪」在站里检索→得到「青龙/玄武」等原型→直接产出小说提示。

### 4）验证方式（30s）
「能跑起来」才算数：健康接口 `200`、写接口 `201`、读回 `total` 自增、删除回原；CORS 只对白名单来源放回头、陌生来源拒；四态（加载中/空/错/筛空）都能在真浏览器看到。

### 5）平台限制（30s）
CloudBase 免费体验版：**3000 点/月，已用 43%**，约 10-24 额度耗尽会停服（数据不丢、次月恢复）；GitHub Pages 主站零费用不受影响；CORS 免费版不能自助加安全域名→用函数精确来源补位解决。

### 6）后续优化计划（30s）
① 把前端收藏从 localStorage 接上 CloudBase（打通端到端持久化）｜② 真登录 token 替换临时 `?user_id=`｜③ 数据导出按钮 / 完成率统计（余力加练）｜④ 真外部热搜（需新建表＋定时任务）｜⑤ 到期前续费或迁出后端。

## 五、结营复盘（板块④）

**28 天最大的一个认知改变：把「写对的代码」换成「能跑起来且我证过的证据」。**
- 前几周习惯「代码写完了＝事做完了」；后几周被 CORS、5 分钟计费窗口、回滚演练反复教育：**没实打的都可能是假的**，写对 ≠ 通。于是养成「每一项结论都要指到文件/命令输出/线上地址，不留一句‘应该没问题’」。
- 第二个改变：**AI 代理也要替人省着花云资源**——免费版按 5 分钟窗口计费，一次窗口 ≈14 点，所以验证要攒着打、别反复刷检查台。这是把「工程素养」从代码扩展到「花钱的边界」。
