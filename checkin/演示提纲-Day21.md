# 演示提纲（Day 21 · 3–5 分钟）

> 面向：本周学习打卡 / 同伴评审。
> 结构：**用户问题 → 核心流程 → 提示词改写 → 验证方式 → 本周未完成项**（前四段即交图要求的四段结构）。

## 0. 一句话定位（开场，不进四段）

本周（第 3 周）从「纯静态站点」跨到「有公网后端」：建了 PostgreSQL 两张表、上线读+写接口、把代码拆成接口层/数据层、做了一个公网检查台让你肉眼看到后端在动。

## 1. 用户问题（约 30 秒）

写网文的人查完神仙/妖怪资料，想「收藏」下来慢慢用——但收藏只存在自己浏览器里，**换设备就没了**。
→ 本周要回答：能不能把收藏存到公网、换设备也在？

## 2. 核心流程（含一次真实写入 + 刷新持久化，约 2 分钟）

现场打开公网检查台 URL，演示三格：

- **健康格**：`GET /api/health` → 「服务正常（yishou）」——证明云函数在。
- **favorites 表格**：`GET /api/favorites?user_id=…` → 显示 N 行真实数据——证明读得到真库。
  - 强调：在数据库控制台改一行，刷新页面就跟着变（契约 `cache-control: no-store`，不缓存）。
- **写入测试格**：点「写一条进收藏表」
  - 首次 → **201**，写进库；下方 favorites 表格重拉，新行出现（**真实写入 + 刷新持久化**）。
  - 再点一次 → **409**「该条目已在收藏中」（数据库唯一约束在工作，没堆垃圾行）。
- **热门榜**：`GET /api/hot` → 被收藏最多的条目 Top N（纯聚合，不含任何个人信息）。

## 3. 提示词改写过程（约 1 分钟）—— 本周我怎么把需求翻成给 AI 的提示词

- Day 16：从「做个后端」→ 改成「**先定契约再建表**（`api-contract.md` §2 为唯一真源）」，避免代码和库漂移。
- Day 17：从「直接拼 SQL」→ 改成「**用 CloudBase PG 网关、不连库也能本机断言**」，逼出 `api-local-test`。
- Day 19：从「函数里写满 SQL」→ 改成「**把查库拆成独立 repository 层，接口层零 SQL**」，触发分层重构 + `refactor-fingerprint` 逐字节比对。
- Day 20：从「函数里写 `*` 通配 CORS」→ 改成「**交给网关反射可信来源、禁通配符**」，解决浏览器跨域被拒。

（这段就是 vibe coding 的核心：需求越具体、越点名代价，AI 给的架构越好。）

## 4. 验证方式（约 30 秒）

- **本机**：`node cloudbase/tests/api-local-test.js`（93/93）、`refactor-fingerprint.js`（22/22）。
- **线上**：`node cloudbase/tests/online-regress.js`（9/9 真打公网地址）。
- **公网肉眼**：检查台三格（健康 / 读 / 写）+ 热门榜。
- **同伴**：打开检查台 URL 填三行结论（能否打开 / 能否真实读写 / 有无报错）。
