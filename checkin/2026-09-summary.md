## 横向归纳

### 反复出现的主题

1. **"怎么证明它对"比"写出来"更贵。** 09-22 到 09-27 六天里，真正吃掉时间的几乎都是验证工具而不是业务代码：`--window-size=390` 演假故障、dump-dom 抓不到中间态、Edge 复用 profile 吃旧缓存、文本模式读写造成假 diff、iframe 刷新让转场不再推进。这是本月最隐蔽的一条主线，也是最后被资产化的一条。
2. **截图与交付物系统性迟到。** 12 天里至少 7 天提到欠图 / 废图 / 拿不到地址栏。09-16 跳过补拍、09-17 欠仓库首页、09-18 又欠两张、09-19 PRD 截图未截、09-24 让宝哥截三轮全是废图、09-25 折腾八轮被骂、09-26 发错东西、09-27 仍拿不到地址栏。
3. **先下结论再找依据 → 返工。** 09-19 目录名判断草率、09-20 版权口径来回改、09-21 样图在暗—淡—厚—亮之间四轮、09-22 视觉三轮推翻、09-24 只量了 1280 和 390 两档、09-25 用"有点小"这种不可量化的词起手。同一个毛病，换着壳出现了六次。
4. **文档与实现不同步。** 09-19 PRD 与 `yizhi/` 骨架脱节、09-22 挑出六处文档与代码对不上、09-24 设计规则散在各处需要重新收敛。文档是写完就扔，不是拿来对账的。

### 明显的变化

- **验收方式**：月初是"打开看看、看着对"；月末是真实 CSS 像素、对比度比值、DOM 指纹哈希、逐像素 bbox 差异。判断标准从主观变成了可复现的数字。
- **资产意识**：月初只交作业；月末开始沉淀可复用件——`tools/postprocess-art.py`、`tools/自检记录/`、技能 `local-web-verify`、技能 `yizhi-filter-check`。从"做完这一件"转向"下次不用重做"。
- **协作方式**：09-22 定下"选项 + 代价 + 建议"三段式之后，09-25 的六档量测、09-27 的开工前三件事拍板，都是先摊选项再动手，不再边做边改主意。
- **产品观**：09-18 从"资料越多越好"翻成"查得准"；月末从"跑起来就行"翻成"四态齐备 + 交互可信"。标准一路往上抬。
