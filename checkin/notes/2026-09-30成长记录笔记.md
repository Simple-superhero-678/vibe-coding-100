2026-09-30成长记录笔记

今天的题目是「公网地址第一次打开时，你第一个想确认的是哪一件事」。我的答案很具体：先确认回话的到底是不是我传上去的那一份东西——不是有没有报错，是「这个地址背后到底站着谁」。

第一段就磕在环境上。实名认证比预想的麻烦，姓名和证件号必须完全一致，反而地址、行业这些随便填不影响结果。真正卡住的是免费体验版：我以为是 0 元直接下单，点进去才发现改成了要用兑换码领，得先去公众号拿码。弹窗上有行小字当时看着不起眼——「环境创建后不可切换数据库类型」。我停下来想了想，选了 PostgreSQL，因为之前写的预备方案里推荐的那条路就是它。现在回头看，这行小字是今天最该被认真读的一句话，选错了不是改配置能救的。

云函数这一环让我改了两次认知。控制台里能创建的模板只有「HTTP 云函数」一种，自带 scf_bootstrap 启动脚本、自己起一个 HTTP 服务，我事先照着老教程准备的 exports.main 写法根本贴不进去，入口不是一回事，只能把代码改成 web server 版。挂路由时又差点栽：表单里「关联资源」默认是「云托管」，得手动切成「云函数」再选自己那个，不切就白挂。等了几分钟，浏览器打开先弹一张「安全提示」中间页，点确定访问，才看见那行 {"ok":true,"service":"yishou"}。那一刻才算真正知道后端活了。

传前端是最乱的一段，也是今天最有收获的一段。Windows 那个「选择要上传的文件夹」对话框，我把路径粘到地址栏回车，报「Windows 找不到」。我以为是中文路径的毛病，把文件复制到 D 盘一个纯英文短路径下再试，还是同一个报错。折腾两轮才反应过来：那个框根本不是地址栏，是搜索框，粘路径等于让它去搜一个叫这个名字的东西。改用鼠标从左边一级一级点进去，一次就过了。

更值得记的是接下来这一下。文件传完了，我拿云函数的那个域名去访问页面，首页、样式、数据全是 404，当下第一反应是「没传成功」。其实域名根本不是一个——云函数走的是 HTTP 网关那个域名，静态资源在另一个域名下，只是名字长得很像。换对地址之后全部 200，手机打开也正常。这件事正好回答今天的题目：公网地址打开时第一个要确认的，是「我用的是不是这个服务真实的地址」，而不是「有没有报错」。404 和「没传上去」之间，隔着一整个我以为。

还有个小尾巴：上传时平台把文件夹名也带了上去，站点实际落在 /cbsite/ 这一层下面。我本来想铺平，查了一遍发现全站引用写的都是相对路径，放子目录照样跑，就留着不动了。

做得不好的地方有两个。一是那个文件夹对话框，我在同一个错觉上试了两次才回头想「是不是我理解错了这个框」，中间还发了脾气，其实是没先停下来看清楚。二是接口契约里后端形态还悬着——预备方案推荐的是直连托管数据库那条路，而我今天开通的是云函数这条路，两条都能落地，但 Day 16 建表之前必须先定一条，不能含糊着往下走。明天先把这个决定做掉，再补跨域。
