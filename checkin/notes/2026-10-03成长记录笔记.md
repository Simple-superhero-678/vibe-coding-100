2026-10-03成长记录笔记

今天给 /api/favorites 加上第二个方法：POST，让收藏能被写进去。三件事，实现、部署、验证。实现按契约走，缺字段回中文提示、防重复回 409、成功回 201，本机拿带唯一约束的内存表跑断言，从 88 条加到 93 条全过。写完自测全绿，我以为今天最轻松的一段就是部署，结果这一天才真正开始。

部署完线上回 443，响应体是空的。同环境另外两个接口都正常 200，只有这一个，怎么都不通。我按顺序排了十一个怀疑：代码有 bug、代码包坏了、路由配错、函数配置错了、函数资源坏了、函数名被占了、环境变量有问题、代码体积超了、Node 版本不对、换条部署通道试试——把十一样全试完，逐条都排掉，还是 443。最后才想起来看那个启动脚本，它是 Windows 换行符，多出来的回车被当成文件名的一部分，容器里那句「启动 node」等于在找「index.web.js加一个回车」这个名字，node 找不到文件，容器根本没起来。前面十一个怀疑之所以全落空，是因为它们都在查「我的代码对不对」，没有一个在查「容器有没有起来」。今天最值钱的一条判据就这一句：443 而且响应体是空的，是容器没起来，不是代码逻辑错——代码错了会回 500，会带错误信息，不会这样干干净净地死掉。

第二个坑在验证里。重复提交本该回 409，实测回了 500。原因是本地自测时我给假查询器编了个错误码形状，写的是「23505」，而真实网关回来的是「DATABASE_23505」，多一层前缀，我的判断等号一比就认不出，掉进兜底的 500。第一次跑就过的断言，骗的其实是我自己：假接口只会回我心里想到的那个形状，想不到的形状它一辈子不会回。后来把真实抓回来的原文一字不改地贴进断言，又加了响应头做第二个来源，才把这条钉住。

修好之后顺着往下挖，发现换行符这件事不是偶然。仓库的 Git 配置里开着自动转换，每次拉代码、切分支，它都会把那个启动脚本悄悄转回 Windows 换行符，也就是说今天修好，明天一拉又是坏的。根子不在编辑器，在版本控制这层。加了一个配置文件把这个脚本的换行符写死成 Unix 风格，才算堵上。

拉胯的地方有三处。一是排障方向从第一步就跑偏了，我把「函数资源坏了」写进当天结论，还列了六条证据撑着，结果证据本身都成立，方向全错，隔天才推翻；证据够多不等于结论对，缺的是「还有哪一层我没看」。二是这个换行符的坑，本质上是同一件事的第三次：工具链的坑不在工具本身，在自带的那套默认配置里。三是推送我又默认沙箱推不上去，劝自己手动来，你网络稳定后一条命令就过了——把没验证过的结论当默认，跟前两个毛病是同一个。明天把契约里那五项没对齐的欠账还掉。
