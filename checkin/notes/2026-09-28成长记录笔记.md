2026-09-28成长记录笔记

今天的题目是「页面之间怎么切换」。在这之前整站只有一个地址：点五个 tab 只是把内容换掉，地址栏永远停在 index.html，链接发不出去、刷新就弹回异兽部、后退键没得退。今天要把地址栏和页面状态接起来。

选切换方式时摆在面前三条路：hash 路由（#/部/神仙）、history 真路径（/部/神仙）、三个独立 HTML 文件。我选了 hash，理由不是它更现代，恰恰相反——站点挂在 GitHub Pages 上，是纯静态托管，没有服务端能做改写，真路径一按刷新就是 404，得额外做兜底页还得改发布流水线伺候它。而 hash 后面的部分浏览器压根不发给服务端，刷新不丢，成本最低，还白送一件事：每次改地址都自动进历史，「返回上一页」不用自己写。三个独立 HTML 那条路最先被我否掉，每页都要重新初始化，缓存和收藏状态全要重来，为了地址栏好看不值得。

最后落地是四条能独立访问的地址：五部浏览、全站检索、收藏夹、单条详情。详情那条最有意思——做完之后每条内容有了自己的链接，可以直接发给别人，打开就是那一条。顺手把余力项也做了：详情面板顶上加了「异兽部 › 九尾狐」这样的面包屑，点部名能跳回该部浏览。

另一件大事是把数据的四种状态补齐。之前只有「正常」和「加载中」，今天补上「空」和「错误」，而且刻意把它们分清：空是「读到了但里面没内容」，错误是「压根没读到」。这两句话的出路完全不同——空的出路是换筛选、换部、点相近条目；错误的出路只有重试，而且必须把原因写出来。这不是文案洁癖：把空说成错，人会去查一个根本没坏的东西；把错说成空，人会以为数据真的没了。本地读数据只要十几毫秒，加载中那一瞬肉眼看不见，错误态以前还得把数据文件改名才造得出来，所以今天加了一个只在本机生效的调试开关，地址后面挂 ?态=慢/错/空 就能把三种状态摆出来给眼睛看，线上完全忽略这个参数。

今天踩的坑分三类。第一类出在地址栏：把中文写进地址之后，读回来的其实是百分号编码形式，我拿它和原始字符串比，永远判成「不一样」，于是每点一次同一个按钮就往历史里塞一条重复记录——后果是后退键要按好几次才出得去，而且不报错。第二类栽在原生弹窗上：关掉详情面板后要把地址收回来，这事挂在弹窗的关闭事件上，结果详情不收回、收藏面板却是好的。查下来是关闭时紧跟了一句把元素从页面移除，元素一离开文档，那个事件就不再派发了。同一个文件里两种表现，特别容易误判成路由写错了。第三类是异步错位：路由接上后触发渲染的地方一下变多了，快速连点两部会看到「页面显示神仙、地址栏写着妖怪」，也不报错，加了一道「渲染代号」守卫才压住。

顺带挖出两个潜伏的真 bug：检索把「五部都读到了但都是空」当成了「五部都没读到」，直接报「检索暂时不能用」；收藏夹把「条目没取到」当成「这条已下架」，让人以为收藏丢了。都是判据写得太粗，改完各自又回归了一遍。

今天还有个小插曲值得记：回归自检的三个脚本原来躺在临时目录里，它们依赖的探针页被我上一次收尾时当成垃圾删掉了。结果重跑回归时十一档全红、整轮只跑十二秒——症状极像产品代码被改坏，实际只是取样器没了。这件事让我明白「用完即删」这个习惯得看对象：验证脚本可以删，但它依赖的取样器要跟着脚本一起存好，否则下次不是省事，是白查一轮。后来我把脚本和探针页一起搬进了正式目录，跑之前自动拷进去、跑完自动删掉。

做得不好的地方还是老毛病：今天要交的截图没交齐。视图切换和正常态两张用线上站截了，剩下加载中、空、错误三张必须在本地起服务才截得到，我卡在起服务那一步就没往下走，最后选择跳过。这跟前面几次「截图不合格就跳过」是同一个毛病，得改。

今天最实的收获是那句「空不等于错」。写下来才发现它决定的不是文案，而是代码怎么判断、界面给不给出口。另外，路由看着只是给页面加了个地址，实际上它把「现在显示的是什么」从一个随手改的变量变成了唯一真源，后面很多状态不同步的麻烦跟着一起消掉了。09-27 记的那笔账还挂着：详情面板缺「命中理由」，等技能自检那条链路能自己跑起来再说。
