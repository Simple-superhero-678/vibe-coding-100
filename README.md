## 一、本地怎么跑起来

**必须起一个本地 http 服务，不能双击 `yizhi/index.html`。**

```bash
cd yizhi                      # 关键：服务根目录是 yizhi/，不是仓库根
python -m http.server 8000 --bind 127.0.0.1
```

然后浏览器打开 → **http://127.0.0.1:8000**

- 停服务：回终端按 `Ctrl+C`
- 端口被占：换 `8001`、`8002`……
- `python` 命令不存在：试 `py -m http.server 8000`

### 为什么不能双击打开（Day 7 实测）

| 打开方式 | 结果 |
|---|---|
| 双击 `yizhi/index.html`（`file://`） | ❌ 页面只剩空骨架——五部 tab、筛选条、卡片**全不出现** |
| 同上，但浏览器加 `--allow-file-access-from-files` | ✅ 完全正常（`站况 = 异兽部 · 12 条`，卡片出图） |
| `http://127.0.0.1:8000/` | ✅ 完全正常 |

原因：页面是 `type="module"` 的 ES 模块，数据用 `fetch` 读 `data/*.json`。`file://` 下浏览器默认**把这两样都拦掉**（origin 是 `null`），所以 JS 一行都没跑。加那个浏览器参数就正常 —— 证明是浏览器的安全策略，不是代码写错。

⚠️ 这与 `PRD.md` §8.6「本地双击能打开」不一致。**M7 已到期，这条现在摆上桌待拍板** —— 见 `TECH_DESIGN.md` §14 第 5 项（三个选项与代价都列好了）。**动手改架构之前先问宝哥。**

### 两套图源

| 在哪打开 | 用哪个图片目录 | 说明 |
|---|---|---|
| `http://127.0.0.1/…`（本地） | `assets-private/` | 《观山海》原图，只在本机，`.gitignore` 挡住，**永不入库、永不上公网** |
| `https://`（将来线上） | `assets/` | AI 生成图 / 公版古籍图，进 git、可公开 |

私有图没放时**逐图**自动回退公开图，所以本地不会出现破图。
强制看另一套：地址后加 `?图源=public` 或 `?图源=private`。

### 验收自己怎么试

1. **五部**：点五个 tab，每部形态不同 —— 异兽是网格，神仙是树，神话是横向时间轴，妖怪按六类分组，境界是一根竖轴。
2. **境界的双序列**：进境界部，点工具条上的「真丹道」 → 轴从 9 阶变成 5 阶，**阶章从阿拉伯数字方框变成朱砂实印的「一等/二等」**，底下注释换成《钟吕传道集》那句。
3. **全站检索**：搜「蛇」→ 3 条，跨两个部（白蛇 / 李寄斩蛇 属妖怪，旋龟 属异兽）。搜「zzz」→ 零结果，但给出口。
4. **详情 + 转场**：点任意一张卡片 → 看到过场动画 → 约 3 秒落到详情。过程中**点一下屏幕**，应当立即落到详情。
5. **跨部收藏**：搜「蛇」→ 开「白蛇」→ 收藏 → 按 `F5` 刷新 → 计数还是 1，点开收藏夹能看到「白蛇」并且**点得进详情**（这一条在刷新后要靠 id 前缀回捞妖怪部，M6 新逻辑）。
6. **导出有没有出处**：详情里点「复制全文」，粘到记事本里看 —— 应当**同时有原文和出处**。

## 四、怎么加一条数据

1. **先加图**（只有异兽部要）：按条目 id 命名，转成 `.webp`，放 `yizhi/assets/`，同时登记 `assets/SOURCES.md`（来源不明的图不收）。
2. **再加数据**：找到该部对应的 JSON，往 `条目` 数组里追加一条 —— `data/shenxian.json` / `shenhua.json` / `yishou.json` / `yaoguai.json` / `jingjie.json`。

```json
{
  "schema": 1,
  "部": "异兽",
  "更新": "2026-09-22",
  "条目": [
    {
      "id": "yishou-001",
      "部": "异兽",
      "名": "九尾狐",
      "吉凶": "吉祥",
      "图": "yishou-001",
      "别名": ["九尾", "青丘之狐", "妲己"],
      "原文": "青丘之山，有兽焉，其状如狐而九尾……",
      "出处": "《山海经》·南山经",
      "写小说怎么用": "吉兆场面的现成素材……"
    }
  ]
}
```

**五部共用必填**：`id` / `部` / `名` / `原文` / `出处` / `写小说怎么用` / `别名`（可为空数组）。
**A–D 部（神仙 / 神话 / 异兽 / 妖怪）还要 `吉凶`**，四值枚举：吉祥 / 凶恶 / 灾祸 / 无害；不在枚举内的一律当「未分类」（只在无筛选时出现）。**境界部不写 `吉凶`。**
`图` 的值**就是条目 `id`**（`yishou-001` ↔ `assets/yishou-001.webp`），不放扩展名。

**部专属字段**（决定它长在树/轴/分组的哪一格，详见 `TECH_DESIGN.md` §5.2）：

| 部 | 还要填 |
|---|---|
| 神仙 | `谱系`（三清 / 四御 / 职能部）+ `座次`；职能部的还要 `司`（雷 / 斗 / 兵 / 冥 / 山水） |
| 神话 | `类型`（创世 / 始祖 / 洪水 / 战争 / 发明 / 斗争）+ `序`（**段内**序号，段间不排绝对年代） |
| 妖怪 | `形类`（妖 / 魔 / 鬼 / 怪 / 精 / 灵）+ `座次` |
| 境界 | `序列`（网文 / 真丹道）+ `阶号` + `原文性质`（标明是古籍真文还是当代通行设定） |

**改到「分几类 / 分几期」这种说明**（妖怪的六类界定、四期年表）时，改的是 JSON 的**顶层键** `形类释义` / `年表`，不是 JS。

改完刷新页面即可，**没有构建步骤**。

> 唯一的判定口径：每条内容都要能回答「**写小说时我怎么用**」。写不出来，就不该进站。
